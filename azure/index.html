Native Azure integrations

The Azure services NeuralSeek uses

Built-in integrations you configure in the console.

NeuralSeek

  • Azure OpenAI as the model layer

    A supported model provider serving the GPT family. Pick a model at setup, or a different one for each step of an agent, and change it later in configuration.

  • Azure AI Bot Service as the virtual agent

    When the bot has no answer for a question, NeuralSeek answers from your knowledge base. Curated answers export into the bot, and round-trip monitoring flags them when source documents change.

  • SharePoint from inside an agent

    An agent step can list, download or upload files in a SharePoint site with the tenant, site and client credentials you give it, so your SharePoint documents feed a governed workflow.

  • The knowledge bases you already run

    ElasticSearch and OpenSearch for document search, and Pinecone and Milvus for vector search, are all supported in your Azure tenant.

Inside an agent

Microsoft services as agent steps

Add a Microsoft service to an agent as a step, give it credentials and scope, and every run is logged.

Azure Blob List ContainersLists the containers in an Azure Blob Storage account and returns the list to the workflow.

SharePoint List FilesLists the files in a SharePoint site, with the tenant, site and client credentials set on the node. Related nodes download and upload.

Email (Outlook)Sends mail through Outlook from a step in the workflow, so an agent's answer can go out as a message.

Azure models in the model layer

Use Azure models your way

Add an Azure-served GPT model as a card in the configuration, choose the functions it serves, and add a second provider beside it if you like. When prices or models change, you update the configuration and your agents keep running.

Security review answers

Short answers for your security review.

  1. 01

    Is data encrypted?

    +

    Yes, in transit and at rest. Everything that flows to or through the service is encrypted over TLS, and everything stored is encrypted too.

  2. 02

    Is our data used to train anything?

    +

    No. Neither NeuralSeek nor any of its subprocessors use customer data to train models or systems, and generated answers belong to the customer.

  3. 03

    What happens to personal data in a request?

    +

    Content flagged as personal data is handled by the action you configure: flag, mask, hide or delete. Requests that carry personal data for a personalized answer are handled the same way.
