mAIstro

建構 AI 代理程式， 串接自有系統。

用 mAIstro 建構能搜尋、查詢系統並做出決策的代理程式。每個步驟都有自己的模型和防護措施，每次執行也都有記錄。

基本單元

代理程式由節點組成

每個節點就是一個步驟：搜尋、呼叫模型、查詢系統、轉換、分支或迴圈。節點在每種部署方式中的運作方式都相同。

代理程式如何組合

節點、代理程式與多代理程式流程

每一層都使用相同的基本單元，因此一個團隊建構的代理程式，可以成為另一個團隊工作流程中的一個步驟。

  • 節點

    單一步驟，有各自的設定：用哪個模型、哪個來源、哪個門檻。可在視覺化編輯器中建構，也能以 NeuralSeek 的範本語言 NTL 撰寫。兩種方式得到的是同一個節點。

  • 代理程式

    節點堆疊成流程，或並排串接，並可加入條件、迴圈和平行步驟。平行步驟代表一次執行所需的時間，只取決於最慢的節點。

  • 多代理程式

    代理程式可以呼叫其他代理程式，共用變數或各自獨立執行。協調器也能從代理程式登錄中，挑選合適的代理程式，或由多個代理程式組成的計畫。

可檢視的執行

每次執行都有記錄

Inspector 顯示每個步驟：設定了什麼、何時設定、如何處理。治理功能則顯示每個代理程式的執行頻率、回應時間、防護措施觸發次數，以及每次執行呼叫的代理程式。

可控制的項目

正式環境代理程式的控管

團隊要讓代理程式從原型走向正式資料，需要的項目都在這裡。

  • 每個步驟各用一個模型

    選擇每個模型負責哪些工作，在任何節點上覆寫模型，或在 API 呼叫中傳入模型 ID。分類用速度快的模型，撰寫回答則用更強的模型。

  • 由您決定代理程式何時執行

    代理程式在 API 呼叫時執行，或依所設的排程執行，可依分鐘、小時、日或月設定。哪些代理程式自行執行、哪些等待請求，都由自己選擇。

  • 流程中段也有相同的防護措施

    提示詞注入防護、個人資料移除和不當用語過濾，都是可放在工作流程任何位置的節點。擷取到的文件或工具結果，會和問題一樣受到篩檢。

  • 並排比較模型

    選擇多個模型，輸入問題，並排比較回答，同時記錄 token 成本與速度。Seek 和 mAIstro 都適用。

  • 針對每個代理程式的對抗式測試

    將 Red Team Testing 指向某個代理程式，隨時都能執行。Red Team Testing 會回報該代理程式的風險、測試證據與建議的修正方式。每次變更後再執行一次。

關於 mAIstro 的常見問題

團隊在建構第一個代理程式之前會問的問題。

  1. 01

    mAIstro 是視覺化建構工具，還是程式碼？

    +

    兩者皆是。在視覺化編輯器中建構的流程，可以當作 NTL 程式碼閱讀與編輯，也可以轉回來。其他地方需要膠水程式碼的工作，在這裡只是一個審查人員能讀懂的節點。

  2. 02

    一定要從空白畫布開始嗎？

    +

    想要的話才需要。以自然語言描述代理程式，自動建構器就會草擬出來；也可以開啟 Marketplace 範本，指向自己的資料。每個節點都看得見，也都能編輯。

  3. 03

    當這類代理程式多達數百個時會怎樣？

    +

    執行記錄內建於平台，不需要由各團隊自行設定。每次執行都有記錄，延遲會依代理程式和子呼叫拆解，token 與成本也都有追蹤。
