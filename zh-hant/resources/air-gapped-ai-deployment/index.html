在完全隔離的環境中 執行 AI

NeuralSeek · 發佈於 2026年10月4日

對資料要求最嚴格的組織，包括國防、情報、部分政府機關與某些受監管的金融業來說，雲端不是選項，再多的合約保證也改變不了這一點。敏感資料不能離開網路，這就排除了所有只提供 API 的模型與多數代管平台。完全隔離的部署是解答，但真正支援的平台寥寥無幾，也幾乎沒有人把正確做法寫下來。這篇就是完整的說明。

完全隔離究竟是什麼意思

完全隔離，指部署環境沒有任何通往公用網際網路的路徑：沒有模型 API 呼叫、沒有遙測、沒有授權檢查、執行期間不下載套件，沒有例外。系統需要的一切都事先鏡像到您的網路內：容器映像檔、模型權重、嵌入模型，以及每一項相依套件。

這比「地端」或「私有雲」要嚴格得多，後兩者通常仍保留某些對外路徑，而且往往依賴這些路徑。這是徹底的網路隔離，值得為此費心的原因在於它可以證明：您可以用網路政策向稽核人員示範，而不只是畫張圖來說明。

對架構的影響是，隔離必須是第一項限制，而不是之後才加上的設定。下面幾乎每一項設計決定都由此而來。

協調管理：基礎

先從負責排程與擴充工作負載的部分談起。容器把每個元件封裝成可攜的映像檔；Kubernetes，或其經強化的企業版本 OpenShift，在您自己的伺服器與 GPU 上協調這些映像檔。

關鍵細節在於登錄庫。您要在網路內架設私有的容器登錄庫，並把每個映像檔都鏡像進去，讓任何 pod 都不會嘗試從外部拉取。這聽起來微不足道，卻是多數完全隔離的嘗試最先失敗的地方，通常是因為某個基礎映像檔或附屬容器，是沒人知道存在的。OpenShift 在受監管環境中佔有一席之地，是因為它預設採用受限的安全情境、整合映像檔簽署與內建政策，因此後面談的強化措施有更好的起點。

模型服務：開放權重，在叢集內

因為沒有可呼叫的託管模型，您得自行提供開放權重的模型。vLLM 或 Hugging Face 的 Text Generation Inference 這類推論伺服器，會以叢集內服務的形式執行，並具備 GPU 排程、請求批次處理與自動擴充。

權重從事先備妥的地端儲存載入，執行期間絕不對外下載。GPU pod 的規模依模型與實際需要的並行量決定，而不是依現有最大的模型決定，並且只在叢集內部網路開放推論服務，因此原則上網路之外的任何地方都連不到。

不離開網路的檢索

模型能發揮多少用處，取決於它能作為依據的資料，因此檢索架構也必須在您的網路之內：向量資料庫、在叢集內提供服務的嵌入模型，以及為文件建立索引的匯入管線。

每個步驟（嵌入、儲存、查詢）都在您的網路內發生，也就是來源資料在任何時間點都不會傳送到別處。這正是一般離線聊天機器人（用處有限）與能依據機密或受監管資料回答的系統之間的差別，也是這種部署存在的原因。

強化措施：不只隔離，更要站得住腳

隔離已經完成了大半。強化措施則讓您能逐項證明，對象是一位職責就是不輕易相信您的人。

  • 以網路政策限制東西向流量，只有必須互相通訊的元件才能通訊，被入侵的 pod 也就連不到模型或索引。
  • 以簽署與准入控制確保映像檔來源，即使未經驗證的映像檔進入了登錄庫，也無法執行。
  • 把機密資訊存放在叢集內加密封存的儲存區，而不是環境變數或資訊清單，後者會出現在記錄與備份中。
  • 啟用完整的稽核記錄，讓每一次推論與每一項設定變更，都能對應到身分與時間。

多數指南沒寫到的那一層

執行模型是基礎架構的問題，也是比較容易的那一半。網路隔離了，治理並不會因此變得不必要。完全隔離的助理仍可能依據薄弱的檢索結果信心十足地回答，仍可能把某個業務單位的資料呈現給另一個單位，仍可能把憑證寫進記錄，也仍可能讓您無法重建它去年三月做過什麼。

所以網路內部要有與外部相同的控管：設定信賴度下限，低於下限時系統選擇不回答；各客戶或各部門之間的文件隔離；遮蔽；以及完整的互動記錄。NeuralSeek 透過同一個容器部署到同一個叢集，在完全不對外連線的情況下提供這一層，包括用您自己的資料，而不是公開排行榜，來比較您已備妥的開放權重模型。

基礎架構讓完全隔離的 AI 成為可能。治理則讓它能安心地交到人們面前使用。
