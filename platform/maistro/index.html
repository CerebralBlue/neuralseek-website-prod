The building block

Agents are built from nodes

Each node is one step: search, call a model, query a system, transform, branch or loop. Nodes work the same in every deployment.

How agents fit together

Nodes, agents and multi-agent flows

The same building block at every level, so an agent one team builds can become a step in another team's workflow.

  • The node

    One step with its own settings: which model, which source, which threshold. Build it in the visual editor or write it in NTL, NeuralSeek's template language. Both give you the same node.

  • The agent

    Nodes stacked into a flow or chained side by side, with conditions, loops and parallel steps. Parallel steps mean a run takes only as long as its slowest node.

  • The multi-agent

    Agents can call other agents, sharing variables or running separately. An orchestrator can also pick the right agent, or a plan of several, from your agent registry.

What you control

Controls for production agents

What your team needs to take an agent from prototype to production data.

  • A model per step

    Choose which jobs each model does, override the model on any node, or pass a model ID on an API call. Use a fast model to classify and a stronger one to write the answer.

  • You decide when agents run

    An agent runs when called from the API, or on a schedule you set by minute, hour, day or month. You choose which agents run on their own and which wait for a request.

  • The same guardrails, mid-flow

    Prompt-injection protection, PII removal and the profanity filter are nodes you can place anywhere in a workflow. A retrieved document or a tool result gets screened the same way a question does.

  • Compare models side by side

    Select models, enter a question and compare their answers side by side, with token cost and speed recorded. It works for both Seek and mAIstro.

  • Adversarial testing per agent

    Point Red Team Testing at an agent and run it whenever you like. It reports the agent's risks, the test evidence and recommended fixes. Run it again after every change.

Common questions about mAIstro

What teams ask before they build their first agent.

  1. 01

    Is mAIstro a visual builder or code?

    +

    Both. A flow built in the visual editor can be read and edited as NTL code, and back again. Work that would take glue code elsewhere is one node a reviewer can read.

  2. 02

    Do we start from an empty canvas?

    +

    Only if you want to. Describe the agent in plain language and the auto-builder drafts it, or open a marketplace template and point it at your data. Every node stays visible and editable.

  3. 03

    What happens when we have hundreds of these?

    +

    The run record is built into the platform, so no team has to set it up. Every run is logged, latency is broken down per agent and child call, and tokens and cost are tracked.
