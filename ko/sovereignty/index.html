데이터 주권과 AI 주권

AI를 자사 환경 안에서.

NeuralSeek는 고객의 클라우드, 고객의 리전, 자체 하드웨어에서 실행됩니다. 인터넷에서 분리해도 계속 작동합니다.

도입 문의하기

배포

데이터가 있는 곳에서 실행됩니다.

데이터가 이미 있는 곳에서 운영할 수 있습니다. 클라우드 계정이든 잠긴 전산실이든 같은 소프트웨어가 모든 기능과 함께 실행됩니다.

  1. 01

    도입을 결정하기 전에 동작을 확인할 수 있나요?SaaS

    NeuralSeek가 GCP, Azure, AWS, IBM Cloud에서 운영하는 SaaS로 시작할 수 있습니다. 직접 운영할 때와 같은 소프트웨어이므로, 데이터 상주가 요건이 되면 다시 구축하지 않고 자사 환경으로 옮기면 됩니다.

  2. 02

    자사 클라우드 계정에서 자사 키로 실행할 수 있나요?프라이빗 클라우드

    같은 컨테이너를 자사 계정에서 자사 네트워크 정책과 키 관리 아래 실행합니다. 격리된 환경이면 어디든 가능합니다. 검색, 로깅, 감사 추적도 자사 리전에서 함께 실행되며, 호출할 모델도 직접 정합니다. 민감한 작업에는 직접 호스팅하는 모델을, 나머지에는 클라우드 모델을 쓰고 작업별로 전환할 수 있습니다.

  3. 03

    정부 규정상 데이터가 국경 안에 있어야 합니다.소버린 클라우드

    자사 레지스트리에서 규제 기관이 이미 인정한 리전이나 사업자로 배포합니다. 운영과 비운영 환경은 물론 고가용성과 재해 복구까지 모두 현지에 있으므로 데이터가 국경 안에 머뭅니다.

  4. 04

    이미 운영 중인 플랫폼에 맞을까요?OpenShift

    NeuralSeek는 전체가 컨테이너화되어 있어 Red Hat OpenShift에서 다른 규제 대상 워크로드와 함께 실행됩니다. 어드미션, 네트워크, 시크릿 관리 규칙이 클러스터의 다른 워크로드와 똑같이 적용됩니다.

  5. 05

    인터넷에서 분리하면 어떻게 되나요?인터넷과 완전히 분리된 온프레미스

    계속 작동합니다. 방화벽 안쪽에서, 또는 하드웨어와 소프트웨어가 함께 제공되는 IBM Fusion 어플라이언스 한 대로 오프라인에서 실행됩니다. 오픈 모델을 자체 GPU에서, 벡터 데이터베이스도 자체적으로, 모든 것이 건물 안에 있습니다. 모델을 로컬에서 실행하면 그 모델에는 토큰당 요금이 들지 않습니다.

데이터는 둔 곳에 그대로 있습니다

NeuralSeek는 고객 환경 안에서, 고객이 고른 리전이나 자체 건물의 하드웨어에서 실행되며, 검색, 오케스트레이션, 로깅, 감사 추적도 그곳에서 함께 실행됩니다. 로그는 고객이 소유한 저장소로 갑니다. 직접 호스팅하는 모델을 연결하면 모든 호출도 내부에 머뭅니다.

AI 주권

모델을 직접 고르고 바꿉니다

모델은 고객이 고르며, 원할 때 언제든 바꿀 수 있습니다.

  • 설계부터 모델에 종속되지 않음

    원할 때 기반 모델을 교체할 수 있으며 다시 구축할 필요가 없습니다. 데이터, 가드레일, 애플리케이션은 그대로입니다. 작업별로 라우팅할 수도 있습니다. 민감한 작업은 직접 호스팅하는 모델로, 나머지는 호스팅형 모델로 보냅니다.

  • 자사 모델 제공업체 API 키

    모델 제공업체의 키를 직접 가져와 사용하면 계약 관계와 그에 따른 이용 권한을 고객이 갖습니다.

  • 자체 GPU의 오픈 모델

    오픈소스 모델을 소유한 하드웨어에서 다른 구성 요소와 나란히 실행하면 모든 모델 호출이 자사 네트워크 안에 머뭅니다.

구매 담당자가 자주 묻는 질문

모델, 데이터, 통제에 대한 짧은 답변입니다.

  1. 01

    의존하는 모델이 중단되거나 제한되면 어떻게 되나요?

    +

    설정 하나를 바꾸면 됩니다. 모델은 컨테이너 안의 한 층이라서 모델이 바뀌어도 데이터, 가드레일, 애플리케이션은 그대로입니다. 오픈 모델을 자체 GPU에서 실행하면 의존하는 모든 것이 자사 환경 안에 남습니다.

  2. 02

    법원이나 기관이 제공업체에 데이터를 요구하면 어떻게 되나요?

    +

    호스팅형 모델 제공업체는 고객이 정하지 않은 보존 정책에 따라 질의 기록을 자체적으로 보관합니다. 모델을 자사 환경에서 실행하면 유일한 사본은 로그 저장소에 있는 것뿐이며, 고객의 정책이 정한 기간만큼 보관되고 제3자는 사본을 갖지 않습니다.

  3. 03

    제공업체가 모델을 바꾸면 답변도 달라지나요?

    +

    고객이 원하지 않으면 달라지지 않습니다. 호스팅형 모델은 업데이트, 재조정, 부하로 인한 지연처럼 모르는 사이에 바뀔 수 있습니다. 자체 하드웨어의 모델은 테스트한 버전 그대로 유지됩니다. 새 모델이 나오면 고객의 일정에 맞춰 테스트하고, 통과하면 전환합니다.

  4. 04

    이미 여러 제품에서 AI를 쓰고 있습니다. 무엇이 다른가요?

    +

    AI 도구마다 데이터 경로, 계약, 검토가 따로 있습니다. 자사 환경의 플랫폼 하나라면 검토도 한 번, 감사 추적도 하나, 확인할 곳도 한 곳입니다.

  5. 05

    AI를 막아 두면 직원들이 개인 도구를 쓰지 않을까요?

    +

    그런 경우가 많습니다. 도구를 차단해도 소용없지만, 승인된 도구를 제공하면 개인 도구 사용을 줄일 수 있습니다. NeuralSeek는 자사 환경에서 실행되며 모든 답변에 가드레일, 로깅, 거버넌스가 적용되므로 첫날부터 모든 직원에게 줄 수 있는 도구가 됩니다.

  6. 06

    회의 내용은 어디에 저장되나요?

    +

    다른 회사의 서비스로 실행되는 회의 어시스턴트는 대화를 그 서비스가 실행되는 곳으로 보냅니다. NeuralSeek 기반 어시스턴트인 NeuralWorks는 고객이 제공한 모델로 자사 환경에서 회의를 준비하고 후속 작업을 처리하므로 대화는 자사 서버에 남습니다.

  7. 07

    고객 데이터로 학습하나요?

    +

    아니요. NeuralSeek와 하위 처리자는 프롬프트, 문서, 상호작용 로그를 모델 학습에 사용하지 않습니다. 키는 고객 환경별로 분리되며 모든 배포가 이렇게 동작합니다.
