AWS 네이티브 연동

NeuralSeek가 사용하는 AWS 서비스

기본 제공 연동으로, AWS를 벗어나지 않고 NeuralSeek를 운영할 수 있습니다.

NeuralSeek

  • Amazon Bedrock · 모델

    지원되는 모델 제공업체입니다. 설정할 때 Bedrock 모델을 선택하거나 에이전트 단계마다 다른 모델을 선택할 수 있고, 나중에 구성에서 변경할 수 있습니다.

  • Kendra와 Bedrock · 지식

    관리형 벡터 검색을 위한 지원 지식 베이스로, 청킹, 임베딩, 인덱싱을 AWS 쪽에서 처리합니다. Kendra의 필터는 사용자별로 볼 수 있는 범위로 쿼리를 제한합니다.

  • Amazon Lex · 가상 에이전트

    Lex 봇이 질문에 답하지 못하면 NeuralSeek가 지식 베이스에서 답변합니다. 큐레이션한 답변은 Lex로 내보낼 수 있으며, 출처가 바뀌면 플래그가 표시됩니다.

  • Amazon S3 · 파일

    에이전트 단계에서 지정한 버킷, 리전, IAM 자격 증명으로 버킷의 파일을 읽거나 다시 씁니다.

에이전트 내부

에이전트 단계로 쓰는 AWS 서비스

AWS 서비스를 에이전트에 단계로 추가하고 서비스, 자격 증명, 범위를 설정합니다. 엔지니어가 콘솔에서 보게 되는 카드입니다.

S3 Read File노드에 설정한 버킷, 리전, IAM 키로 S3 버킷의 객체를 워크플로로 읽어 옵니다. S3 Write File은 객체를 다시 저장합니다.

RedshiftRedshift 웨어하우스에 연결해 SQL 쿼리를 실행하고, 데이터를 문장 또는 CSV로 반환합니다.

모델 계층의 Bedrock

원하는 방식으로 Bedrock 모델 사용

구성에서 Bedrock 모델을 카드로 추가하고, 담당할 기능을 고르고, 원하면 다른 제공업체를 함께 추가합니다. 가격이나 모델이 바뀌면 구성만 업데이트하면 되고, 에이전트는 그대로 실행됩니다.

보안 검토 답변

보안 검토를 위한 간단한 답변입니다.

  1. 01

    데이터는 암호화되나요?

    +

    네, 전송 중과 저장 시 모두 암호화됩니다. 서비스로 들어오거나 서비스를 거치는 모든 데이터는 TLS로 암호화되고, 저장되는 모든 데이터도 암호화됩니다.

  2. 02

    고객 데이터가 무언가를 학습하는 데 사용되나요?

    +

    아니요. NeuralSeek와 하위 처리자는 모두 고객 데이터를 모델이나 시스템 학습에 사용하지 않으며, 생성된 답변은 고객의 소유입니다.

  3. 03

    요청에 포함된 개인정보는 어떻게 처리되나요?

    +

    개인정보로 감지된 콘텐츠는 설정한 방식(플래그 지정, 마스킹, 숨기기, 삭제)으로 처리됩니다. 맞춤형 답변을 위해 개인정보가 포함된 요청도 같은 방식으로 처리됩니다.
